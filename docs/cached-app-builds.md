# Cached first-party app builds

MediaSeed 0.1.12 and MediaVPN 0.2.17 retain local, commit-pinned source builds. A small Python stage extracts sorted runtime and build requirements from pyproject.toml. Only that output enters the runtime dependency layer. Ordinary version bumps, Python code and static assets can reuse dependencies while dependency changes automatically invalidate them. The app package is then installed with no dependency resolution, no build isolation and no package index; this keeps its real package version and package-data files.

The first build after upgrading establishes the new layers. A cold or evicted cache still requires dependency downloads. No build-time or update-time speedup has been measured on the production host.

Core 0.6.34's preparation helper points MediaSeed's client-init at the app image and removes its separate build definition. It builds app once, then runs the existing idempotent initializer using that local image with --pull never and --no-deps. This applies to both fresh and older approved Compose configurations. Existing entrypoints, root initialization user, isolated networking, config/secrets volumes and external media mounts remain intact. Normal Core preparation can migrate the shared-image setting without rebuilding an already installed app; independent app updates use their selected commit's image. Stopped apps remain stopped under the existing lifecycle policy.

App Dockerfile optimization is delivered independently through each app's update. Removing the redundant initialization build requires the updated Core helper. Fresh Core installations include the newer app sources; Core upgrades preserve already installed app versions. Native amd64/arm64 still use their matching Python base and dependency wheels, subject to the existing runtime prerequisites. There are no new host requirements or configuration/database migrations.

Regression checks execute the Dockerfiles' real dependency-manifest command for fresh metadata, a version/code-only upgrade and dependency/build-tool changes. Python wheel builds with an isolated build environment and --no-index verify package construction, dependency declarations, version metadata and bundled assets. Mocked host flows verify one app build for fresh/older MediaSeed configurations and unchanged scoped VPN helper handling. Docker Desktop's engine was not running on the development PC, so a full Docker layer-cache hit and production build timing have not been verified here.
